# 任务创建与 Bash 脚本编辑整体方案

日期：2026-11-17。用户已确认实施本方案；实施与验收状态见[当前记录](task-creation-progress.md)，技术依据见[调研报告](task-creation-research.md)。

## 目标与范围

管理员填写名称、确认工作目录、输入脚本即可创建任务。复杂任务在同一表单中添加步骤和配置变量，无须切换简单／高级模式或重复填写。

本轮覆盖 Bash 执行、创建与编辑表单、代码编辑、输入保护和错误定位。静态检查作为后续独立增量。首批不加入流程画布、AI 生成、自动格式化、服务器文件浏览或自动执行。

## Bash 执行契约

- 统一使用 `/bin/bash --noprofile --norc -c <script>`，不提供逐任务解释器选择，不回退 sh。启动时验证该路径可执行且确为可运行的 Bash；缺失时明确提示安装 Bash，服务不进入可受理任务状态。镜像与部署说明声明 Bash 运行依赖。
- 普通任务、Webhook 和 API 任务走同一执行入口。脚本中的 shebang 是文本内容，不用于切换解释器。
- 每个 `commands[]` 元素仍在独立 Bash 进程中执行；每个步骤继承任务目录与变量，步骤覆盖任务，触发白名单覆盖保持原有顺序。
- 前端脚本文本改变后继续生成带 `set -e` 的单个命令；未改时原 commands 数组原样提交。此次不全局追加 `set -u` 或 `pipefail`；需要时管理员在脚本显式声明。`set -e` 按 Bash 本身规则执行，不承诺所有非零状态都会退出。
- 为避免服务环境隐式切换 Bash 模式或加载启动脚本，在最终进程环境中排除 `BASH_ENV`、`ENV`、`SHELLOPTS`、`BASHOPTS`、`POSIXLY_CORRECT` 及导出的 Bash 函数条目；同名任务变量不得绕过过滤，界面与 API 对保留变量给出字段错误。其他变量遵循现有继承规则。该限制属于本提案的新契约，实施时同步校验与使用规范。
- `--noprofile/--norc` 不足以屏蔽非交互 Bash 的 `BASH_ENV`，不能以两个选项替代环境处理。用户需要初始化时在脚本中显式 source。
- 保持进程组取消、超时、同名 FIFO/terminate、任务快照、并行汇总、日志 SSE、落盘失败恢复和管理员授权不变量。

切换影响：既有任务下一次执行使用 Bash，不自动重写任务文件、脚本或历史，也不迁移为持续支持双解释器的协议。旧任务已有合法启动控制变量声明时允许读取，但执行时过滤；再次保存前移除相关声明，其他坏数据校验不放宽。Bash 与 sh 并非完全同义，发布前在独立目录复验代表性旧任务；部署切换前停止接收并处理活动运行，异常退出记录按现有规则标为 interrupted，不自动重跑。

## 创建与编辑流程

采用单页、单一提交边界和一个主要滚动区。编辑容器保留独立的底部操作区，避免长内容把操作推出视口；具体采用宽 modal 还是更完整的编辑容器，由原型在实际断点下确定，不能仅把左右滚动区删除。

```text
新增任务
名称                         工作目录
说明（选填，按需展开）

任务环境变量（2）                       [展开]
应用于所有步骤；步骤可覆盖同名变量

执行步骤                     顺序执行
步骤 1 · 执行脚本
Bash 脚本                              [扩展编辑]
┌─────────────────────────────────────────┐
│  1  …                                   │
│  2  …          脚本主要编辑空间           │
│                                         │
└─────────────────────────────────────────┘
步骤设置 · 继承任务目录：/tmp             [展开]
执行目录：/tmp
步骤环境变量（1）                       [展开]
继承任务变量 2 项 · 本步骤覆盖 1 项
[添加步骤]

执行设置 · 超时 30 分钟 · 等待前次完成  [展开]
───────────────────────────────────────────
[创建任务] [取消]
```

- 新建默认 `/tmp`、30 分钟、等待、顺序执行。目录是需要确认的可见字段，不从浏览器当前目录推断服务器路径。
- 基础字段与步骤不重复套用装饰卡片；说明按需展开，已有非空说明自动展开。脚本排在步骤设置与目录摘要之前；在 1280×720 初次打开、不滚动的场景可见代码输入并能开始编写，底部操作完整可达。
- 默认一个步骤，名称预填“执行脚本”且允许修改。增加步骤时生成当前语言的可编辑名称，已输入内容不随语言切换被覆盖。
- 单步骤脚本始终展开；多步骤展示编号与名称摘要，可独立展开，支持上移、下移和删除。新增后展开并聚焦；最后一个步骤不可删除，最多 100 个。
- 步骤设置包含名称与目录覆盖。目录空值明确显示继承关系；不把继承值复制进覆盖字段。已有目录覆盖在编辑时自动展示，并在折叠摘要显示覆盖状态。
- 多步骤时在步骤区域展示具名的执行顺序选择，提供串行与并行及失败行为说明；单步骤创建不要求理解并行选项，旧任务值仍保留。
- 任务环境变量位于任务信息之后、执行步骤之前，步骤环境变量位于各自步骤内部、脚本之后；两级均有独立具名入口，步骤变量不藏在泛称“步骤设置”的入口内。超时和同名策略按需展开。已修改的设置在摘要中可见，保存始终提交完整可编辑字段。

### 环境变量作用域

- 界面使用“任务环境变量”表达本任务所有步骤共享的变量；不简称“全局”，避免被理解为服务中所有任务共享。示意图中的数量仅为示例，新建时两级均为 0。
- “步骤环境变量”只作用于所属步骤，同名时覆盖任务变量；删除步骤覆盖后恢复继承，不删除任务变量。空字符串是有效覆盖值，不等同于删除。
- 任务区展示任务声明的键值；步骤区展示可展开的只读继承摘要和可编辑的本步骤键值。同名变量标记“覆盖任务变量”，继承项不复制进步骤 env，也不能在步骤内直接修改任务值。
- 折叠摘要分别显示任务声明数、步骤声明数和同名覆盖数。已有非空配置编辑时展开；校验失败自动展开出错的准确作用域。修改任务变量后，各步骤继承摘要立即更新，已有步骤覆盖保持不变。
- 脚本变量补全合并任务与当前步骤的名称，同名去重并标明来源；不包含其他步骤的独有变量，不显示秘密值。
- 实际执行优先级保持为：服务进程环境 → 任务环境变量 → 步骤环境变量 → 本次触发允许覆盖的变量（越后优先）。触发覆盖仍受既有声明白名单限制；任务编辑器展示的是保存配置，不将未来触发值伪装成当前配置。

例如任务声明 `DEPLOY_ENV=staging`、`APP_DIR=/srv/app`，步骤 1 声明 `DEPLOY_ENV=production`：步骤 1 使用 production，步骤 2 未覆盖时使用 staging，两步均继承 APP_DIR。若本次触发按白名单覆盖 DEPLOY_ENV，则该次运行以触发值为准，保存配置不变。

## 脚本编辑能力

优先采用 CodeMirror 6，并以正式 ui 的通用代码字段公开给业务。首批接入前完成最小验证，确认 Shell 模式、输入法、键盘、主题和依赖加载可用后锁定版本。若失败，记录具体问题并返回选型，不以普通文本框冒充已完成代码编辑体验。

首批能力：

- Bash/Shell 语法高亮、行号、等宽字体、当前行提示、查找替换、撤销重做、选区缩进和软换行。
- 桌面约 12–16 行作为原型起点，支持扩展编辑；窄屏按可视空间收敛，操作区不被软键盘遮挡。扩展与恢复复用编辑状态、光标、选区和撤销历史。
- 变量名补全来自任务与当前步骤的已声明变量，插入 `${NAME}`，不展示变量秘密值；不承诺服务器路径、命令或参数自动补全。
- 保留粘贴内容、空白、引号、here-document 和原始换行，不自动 trim、格式化或插入配对字符。智能缩进只启用经 Bash 语料验证的部分，不支持时保留基础缩进。
- 加载失败保留原文并提供重试或明确的纯文本备用输入；按需加载编辑器，具体构建增量与首次可编辑耗时在原型中测量。
- Tab 缩进提供可发现的焦点退出方式。Escape 优先关闭补全／搜索或退出扩展编辑，不误关任务表单；Ctrl+Enter 不绑定真实执行。

Shell 流式高亮模式不等于 Bash 解析器，也不等于诊断器。高亮覆盖数组、`[[ ]]`、函数、变量展开和 here-document 是候选适配的必验项。

## 输入与错误生命周期

- 表单状态由现有 TanStack Form 管理，编辑器只持有编辑交互状态；一个字段一种权威文本来源。受控更新不能在每次按键时重建编辑器或清空历史。
- 未修改脚本的旧 commands 数组原样提交；多个独立命令展示时说明“修改后将合并为一个脚本”，切换主题、聚焦、展开等操作不视作文本修改。
- 必填与格式错误在合适的交互结束时显示；提交时汇总错误，自动展开对应区域并聚焦字段；服务端字段错误保持原有结构化映射。
- 提交期间锁定输入和重复提交；失败保留全部输入并允许重试；成功关闭编辑器并刷新任务列表。列表刷新失败不得误报创建失败。
- 有未保存修改时，取消、关闭按钮、遮罩、Escape 和应用内离开统一确认丢弃；浏览器刷新／关闭使用可用的原生离开提示，注明浏览器限制。取消丢弃继续编辑，焦点回到编辑区。
- 草稿只存在当前编辑会话内，不自动写入 localStorage；确认丢弃或成功后清理。不同任务与步骤状态隔离。
- 新增文案覆盖中文和英文，业务消息属于 tasks，编辑器通用控件消息属于 ui；继承统一主题，不建立业务主题副本。

## 静态检查增量

编辑器稳定后增加手动“检查脚本”，使用本机 ShellCheck 的 Bash 模式，结果提供行列、严重程度、规则编号与定位入口。检查用户原文；若检查生成文本，必须处理 `set -e` 前缀的行号偏移。

检查不执行脚本，不保证目录、命令或部署结果正确，普通警告不阻止保存。请求按文档版本关联，迟到结果不覆盖新内容；错误修改后标为结果已过期。检查器缺失明确显示不可用，不显示通过。文本默认不发送第三方服务。

需补齐可选工具部署契约、GPLv3 交付方式、输入大小／超时／并发限制和 source 文件访问约束后实施；本轮不将 ShellCheck 纳入核心启动依赖。

## 职责与改动范围

| 归属 | 职责 |
| --- | --- |
| tasks 后端 | Bash 可用性检查、进程启动、环境处理与输入校验；保持调度及存储恢复链路 |
| 正式 ui 模块 | 通用代码字段、编辑器加载与销毁、主题／错误／焦点接入、扩展编辑及必要容器能力；统一维护底层依赖 |
| tasks 前端 | 渐进表单、Bash 配置、变量名数据源、原 commands 保留、脏状态、错误定位 |
| 应用 frontend/backend | 保持品牌和通用装配；通过模块默认入口消费，不增加任务专属接线 |
| 文档与部署 | Bash 必备依赖、环境保留项、执行语义、升级兼容说明、模块公开入口与双语资源 |

通用代码字段至少支持受控文本、变更／失焦、标题／说明／错误、只读／禁用、语言扩展、补全源和聚焦定位；不在 ui 内引用 tasks API。准确名称与最小类型在原型后冻结。业务不直接导入 CodeMirror 或 Mantine 内部控件，不编辑 `.redberry/`，不自行修改框架依赖版本。
